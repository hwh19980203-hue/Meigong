# 飞书多维表格到 AI 作图需求流转

> 本页记录飞书需求记录与 Obsidian 知识库之间的衔接规则。以后处理 AI 作图任务时，Codex 必须先读取飞书记录链接，收集生图所需的产品与任务信息，再结合本地知识库生成 Brief 和 GPT 作图提示词。

## 固定飞书入口

飞书需求记录链接：

`https://uikz7wcmjbd.feishu.cn/wiki/CXxdwRjp4iAeBmks0T4crBwgn0d?from=from_copylink`

## 读取优先级

1. 先读取飞书需求记录，按产品编号、ASIN/SKU 或任务名称定位本次作图对象
2. 再读取本地产品页：`wiki/products/`
3. 再读取历史案例页：`wiki/cases/`
4. 再读取规范和模板：`wiki/standards/`、`wiki/templates/`
5. 最后生成作图 Brief、GPT 提示词和缺口补充表

## 从飞书收集的信息

Codex 应优先从飞书记录中提取：

| 信息 | 用途 |
|------|------|
| 产品编号 | 定位任务和归档 |
| 产品名称 | 写入 Brief 与提示词 |
| ASIN / SKU | 命名、追溯和匹配产品页 |
| 目标站点 | 判断语言、尺寸和平台要求 |
| 所属店铺 / 品牌 | 判断视觉调性和品牌一致性 |
| 产品类目 | 匹配合规风险和历史案例 |
| 产品卖点 | 决定图片表达重点 |
| 图片任务类型 | 判断主图、附图、A+ 或广告图 |
| 参考图 / Word 文档 / 实拍图位置 | 确认构图参考和真实产品依据 |
| 开发备注 | 提取必须表达、禁止出现、交付偏好 |
| 交付要求 | 输出尺寸、格式、命名和归档 |

## 缺口处理

飞书记录不完整时，Codex 不直接脑补，应生成 [[wiki/templates/AI作图需求缺口补充表]]，把缺失项分给开发或美工补充。

常见缺口：

- 产品实拍图不足，无法确认颜色、材质、结构和包装内容
- 图片用途不明确，不知道是主图、附图、A+ 还是广告图
- 卖点只有标题，没有画面表达重点
- 没有指定目标站点或输出尺寸
- 没有说明禁忌、合规风险或竞品避让要求

## 冲突处理

- 飞书记录与本地产品页冲突时，优先以最新飞书记录为准
- 参考图与实拍图冲突时，以实拍图为准；参考图只作为构图、场景和氛围参考
- 产品事实无法确认时，写入 Brief 的“待确认/风险”，不要进入最终出图提示词

## 无法访问飞书时

如果当前环境无法打开飞书链接或没有授权，Codex 应明确说明，并请用户提供以下任一材料：

- 飞书页面截图
- 飞书记录复制文本
- 多维表格导出的 `.base`、`.xlsx`、`.csv`
- 产品 Word / Markdown 需求文档
- 产品实拍图文件夹
