# 黑伞美工 Codex 出图协作手册

## 定位

Codex 是黑伞美工部门的辅助工具。

它的核心职责不是单独维护知识库，而是帮助美工部门更快理解需求、更稳生成图片、更高效迭代修改，并通过知识库提高出图命中率、减少返工。

一句话理解：

> Codex 的价值不在“会聊天”，而在“帮你更快做对图”。

## Codex 在美工部门主要做什么

1. 帮我们读需求  
把运营、开发、老板给的零散信息整理成能出图的明确任务。

2. 帮我们做图  
结合参考图、产品资料、历史案例和规则，辅助调用 GPT 或 Banana 生成更接近目标的图。

3. 帮我们改图  
根据反馈做多轮收敛，而不是每次推翻重来。

4. 帮我们少走弯路  
通过知识库调用历史经验、固定母版、失败案例和规范，提高出图成功率。

## 模型定位

当前出图模型分工如下：

- GPT：负责更强调产品准确性、数量准确性、结构约束和参考图还原的任务
- Banana：负责更强调氛围、版式、场景感和 A+ / 场景图探索的任务

模型由美工按任务选择，但选择原则要统一。

基于 [[wiki/cases/773-两套God Bless拉旗装饰]] 与 [[wiki/cases/786-冰激凌水滴化妆包]] 的实际过程，建议按下面方式判断：

### 优先用 GPT 的情况

- 主图、白底图、尺寸图、信息图
- 产品数量、配色、结构不能错
- 已有实拍图、白底图、锁定母版，需要严格参考
- 当前轮次重点是“修准”，不是“找感觉”

### 可以优先试 Banana 的情况

- A+ 氛围图
- 场景图
- 礼品感、节日感、桌面氛围等视觉探索
- 产品主体已经锁定，只需要换背景、换版式、换场景气氛

### 不管用哪个模型，都必须遵守

- 先给参考图
- 先写清楚不可变约束
- 如果产品已有锁定母版，禁止整图重绘产品主体
- 需要高一致性时，优先“锁定产品母版 + AI 做背景/场景 + 分层合成”

## 核心原则

AI 出图效果，80% 取决于输入质量。

以后所有协作都围绕四件事：

1. 你到底要什么图。
2. 产品长什么样。
3. 哪些东西不能改。
4. 哪些地方可以发挥。

## 出图前必须说清楚的事

### 1. 先给参考图，再谈生成

优先提供：

- 实拍图
- 白底图
- 已确认首图
- 历史成品图
- 竞品参考图
- 构图参考图

### 2. 先说“不变的东西”

例如：

- 产品外形不能变
- 材质不能变
- 图案不能变
- 颜色关系不能乱
- 数量不能错
- 配件不能丢

### 3. 再说“想优化的东西”

例如：

- 更高级
- 更饱满
- 更干净
- 更像亚马逊爆款
- 更适合美国市场
- 更适合做 A+

### 4. 一次不要改太多

一次只改 1 到 3 个重点。  
如果一口气改十几项，AI 很容易顾此失彼。

### 5. 不要让 AI 凭空想象产品

只要是产品图，尤其是主图、A+、场景图，必须尽量带参考图。  
产品一致性永远优先于场景花哨。

## 什么是好指令

好指令不是“写得很长”，而是“让模型少猜”。

结合 773 和 786 的出图过程，一条好指令通常有 7 个特征：

### 1. 先定义任务类型

先说清楚这张图到底是什么：

- 主图
- A+ 英雄图
- A+ 信息图
- 场景图
- 细节图
- 尺寸图

不要只说“做一张图”，模型不知道你要卖货、讲细节，还是做氛围。

### 2. 先定义参考图角色

好的指令会明确每张参考图是干什么的。

例如：

```text
Image 1 is the locked product master. Use it as the exact product appearance source.
Image 2 and 3 are real product references for fabric texture, zipper detail, and printed pattern.
Image 4 is composition reference only, not product appearance reference.
```

这一步非常重要。  
同事最容易犯的错，就是把所有参考图一股脑丢进去，但不说谁是主体参考、谁只是风格参考。

### 3. 先写全局硬约束

好的指令会先定义“绝对不能变的东西”。

例如 786 那种写法就比较标准：

```text
Preserve the exact product identity: 12 bags, 6 color designs, 2 bags per design, one zipper and one metal zipper pull per pouch.
Do not redraw the product into a different pouch shape.
Do not add handles, straps, extra zipper pulls, logos, packaging, hands, or accessories that are not included.
```

这类约束的价值是把最容易错的点提前锁死。

### 4. 场景、构图、文案要分开写

好的指令不会把所有要求揉成一段。  
而是拆成几个部分：

- Scene
- Composition
- Text
- Product rules
- Avoid

这样模型更容易稳定执行，也方便后面单独修改某一块。

### 5. 文案要短，不要贪多

实际经验里，图上的英文越多，越容易出错。  
尤其是 A+、信息图、尺寸图，尽量：

- 标题 1 行
- 副标题 1 行
- 标签词尽量短

不要在同一张图里塞太多长句子。

### 6. 一轮只解决一个核心问题

好的指令不是一轮里同时改 10 件事。  
而是当前轮次只盯住一个主目标。

例如：

- 这一轮只修产品外形
- 这一轮只修拉链数量
- 这一轮只修场景氛围
- 这一轮只修文案层级

773 和 786 的过程都说明，多轮收敛比每轮大改稳定得多。

### 7. 明确写出不要什么

很多错误不是因为“没说要什么”，而是因为“没说不要什么”。

例如：

- No logo
- No packaging
- No hands
- No extra accessories
- No changed dimensions
- No new colors
- No second zipper

“Avoid” 部分通常能明显减少返工。

## 好指令的标准结构

以后写指令，尽量按这个骨架：

```text
Task:
这是什么图，用在什么位置

Input image roles:
每张参考图分别负责什么

Canvas:
尺寸、比例、裁切方式

Scene / Composition:
场景、构图、主体位置、信息布局

Text:
标题、副标题、标签词

Product rules:
产品不可变约束

Avoid:
明确不要出现什么
```

## 坏指令和好指令对比

### 坏指令

```text
帮我做一张这个产品的 A+ 图，做得高级一点，好看一点，可爱一点，适合美国市场。
```

问题：

- 不知道是什么模块
- 不知道参考哪张图
- 不知道产品哪里不能变
- 不知道“高级”和“可爱”怎么落地

### 好指令

```text
Create an Amazon A+ hero banner for this product.

Image 1 is the locked product master and must be used as the exact product appearance source.
Image 2 and 3 are real product references for texture, zipper detail, and printed pattern.
Image 4 is atmosphere reference only.

Canvas:
Final crop 970x600 px, wide horizontal layout.

Scene:
Bright pastel tabletop scene with soft dessert-themed accents.
Keep the product group as the hero in the center or lower-center area.

Text:
Main headline only, short and clean.

Product rules:
Preserve the exact quantity, color order, pouch shape, zipper count, and printed artwork.

Avoid:
No logo, no packaging, no hands, no extra accessories, no changed product shape.
```

## 从 773 和 786 总结出的指令经验

### 773 给出的经验

- 只靠文字描述，不足以锁住产品外形
- A+ 和场景图不能默认让模型重画产品主体
- 当产品结构复杂、装饰件多、形状容易漂移时，必须先锁母版
- 好指令要明确“产品由母版提供，AI 只负责背景、版式、氛围”

### 786 给出的经验

- 数量、颜色、拉链数量这类信息必须写死
- “鼓包感”“更饱满”这类目标要配实拍参考，否则模型会自己想象
- 参考图角色分配写清楚后，稳定性明显更高
- 一套提示词里应该有全局硬约束，再加每张图的单独用途

### 最值得同事记住的一句话

好指令 = 任务明确 + 参考图分工明确 + 不可变约束明确 + 不要项明确。

## 标准提需求格式

以后所有出图需求，尽量按这个格式发给 Codex：

```text
我要做的图：
这是主图 / A+ 图 / 场景图 / 尺寸图 / 细节图 / 广告图

产品信息：
产品编号 / 产品名 / 店铺 / 站点

必须参考的图片：
[实拍图路径]
[白底图路径]
[历史成品图路径]
[母版图路径]

这张图的目标：
我希望它传达什么卖点，解决什么问题

绝对不能变的地方：
产品外形 / 图案 / 数量 / 结构 / 配件 / 材质 / 色系

希望优化的地方：
构图 / 氛围 / 光感 / 饱满度 / 高级感 / 文案表达 / 信息层级

输出要求：
先给我你的理解，再生成
或者
先给我提示词草稿，再出图
```

## 五种最常见的出图场景

### 1. 做主图

目标：干净、明确、产品准。

```text
帮我做这款产品的主图。
必须严格参考我给的实拍图和白底图，不能改产品外形。
我要的是更适合电商点击的版本，但产品主体不能漂移。
先告诉我你理解的重点，再开始生成。
```

主图最重要的是：

- 产品要准
- 信息要清
- 排布要稳
- 一眼能卖

### 2. 做 A+ 图

目标：产品一致，卖点更完整。

```text
基于已经确认的主图母版，帮我做 A+ 图。
必须沿用同一产品主体，不允许整图重绘产品。
重点表达这些卖点：
[卖点列表]
场景和版式可以优化，但产品本身不能跑偏。
```

### 3. 做场景图

目标：有氛围，但产品还是对的。

```text
帮我做场景图。
产品必须和参考图保持一致，场景只是辅助，不是重画产品。
我想要的氛围是：
[节日感 / 温馨 / 美式家庭 / 高级 / 明亮 等]
重点让用户理解这个产品适合在什么场景使用。
```

### 4. 做细节图 / 信息图

目标：讲清楚，不要乱。

```text
帮我做细节信息图。
产品要用参考图中的真实形态，不要夸张改造。
重点表达：
[尺寸 / 材质 / 配件 / 结构 / 使用步骤]
整体信息要清楚，优先易读性，不要过度装饰。
```

### 5. 做“改图”而不是“重做”

```text
不要重做，基于当前这张继续改。
保留：
[哪些部分保留]
只修改：
[哪些部分修改]
修改目标是：
[更饱满 / 拉链修正 / 构图更稳 / 产品更立体]
其他地方尽量不动。
```

## 怎么让 Codex 更接近你想要的风格

不要只说“高级一点”“好看一点”，要拆开说。

例如把“高级感”拆成：

- 背景更干净
- 光线更柔和
- 配色更统一
- 排版更克制
- 留白更多
- 质感更真实

把“更适合亚马逊”拆成：

- 主体更突出
- 卖点更一眼看懂
- 文字更少
- 信息层级更清晰
- 不要花哨装饰
- 缩略图下也能看清重点

抽象词可以说，但一定要配具体说明。

## 多轮修改的正确方式

不要每次都推翻重来。  
正确做法是逐轮收敛。

第一轮：先看大方向

- 产品对不对
- 构图对不对
- 氛围对不对

第二轮：修结构错误

- 外形
- 比例
- 数量
- 拉链
- 配件
- 图案

第三轮：修卖点表达

- 信息清晰度
- 细节展示
- 场景匹配
- 文案层级

第四轮：修精致度

- 光影
- 质感
- 颜色
- 版式
- 氛围

可以直接这样要求：

```text
这一轮先不要追求终稿，只看三件事：
1. 产品外形是否正确
2. 构图是否成立
3. 卖点是否清楚

其他细节先不修。
```

## 什么时候必须先读知识库

知识库不是主角，但在这些时候必须先读：

1. 这个产品以前做过。
2. 这个店铺有固定风格。
3. 这个产品已有锁定母版。
4. 这个案例以前踩过坑。
5. 你不确定该用什么画法更稳。

这时可以直接说：

```text
先读这个产品相关的知识库页面，重点看以前的成品、失败点和锁定母版规则，再帮我出图。
```

知识库的作用是提高出图命中率，而不是为了单独写文档。

## 同事最容易犯的错误

1. 只说“做个图”，不给参考。
2. 给了参考图，但没说哪张是主体参考，哪张只是风格参考。
3. 想改很多东西，却不区分“必须不变”和“希望优化”。
4. 每轮都说“重新来”，导致结果越来越飘。
5. 明明产品已经有母版，还让 AI 整体重画。

## 最短工作口诀

- 先给参考图
- 先说什么不能变
- 再说想优化什么
- 一次只改几个重点
- 每轮都让结果更接近终稿
